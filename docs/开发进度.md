两幕均已形成可玩的完整闭环：

**标题 → 第一幕跑跳/射击 → 代签单名字门 → 365 里路倒带名字门 → 奶娃主持人登场 → 三个阶段 → 第一幕结算 →「前往荒野岛」→ 取景框教学 → 断桥导弹 → 「想链接了」路牌门 → 「这是好事呀」货架门 → 荒哥登场 → 第一管血打空 / 假胜利「十倍杠杆」→ 双倍血条第二阶段 → 挂钩弹反 → 真正清空第二管血 → 喝水 / 翻牌 → 第二幕正式结算 → 重试 / 返回标题**

## 2. 已实现内容

### 2.1 舞台与射击手感

- 保留左右移动、二段跳、土狼时间/跳跃缓冲、射击、冲刺（带无敌帧与残影）、梗卡与梗浓度槽
- Boss 房补了横版发布会舞台：褪色巨幕、快递传送带、升降台、讲台、垂下的卷曲面单；阿浣在左、演示物在中、灭霸在右
- 射击首次按下立即出弹，按住稳定连发，松开停火；枪口短闪、扇形弹道、命中闪白与音效沿用原系统
- 普通射击使用轻量反馈；完美弹反保留明显顿帧、震屏和闪白

### 2.2 第一道名字门「代签单」

- 收发室包裹、按铃、机器打印小票，答题时面单留在视野内
- 小票三行：收件人：灭霸 / 代签人：灭建国 / 与收件人关系：父
- 问题「谁替灭霸签了包裹？」，选项含灭霸/灭建国/阿浣/收发员
- 答对盖「代签有效」，尾巴卷走签收联，门闩打开，进入原有三选一梗卡
- 答错可重试；门状态写入 `RunState.door1Passed`，检查点复活后仍可继续
- 这张签收联在 Boss 第二阶段重新展开

### 2.3 第二道名字门「365 里路」

- 玩家先看到近处取件窗口；按铃后窗口沿轨道滑远
- 吐出「取件请绕行 365 里」路线单，纸路一头连窗口、一头缠双轴磁带机
- 问题「按哪个键，能把这条路收回来？」，选项为播放/快进/倒带/录音
- 答对：线轴反转、纸路回卷、窗口拖回、取件铃响，窗口开成 Boss 房入口
- 各自记录 `door2Passed`、奖励、出生点与检查点状态；答错可重试
- 原创吐纸、滚轴、取件铃音效仍由 WebAudio 合成，无外部素材

### 2.4 奶娃主持人灭霸（紫色重绘）

- Boss 外观改为报废育儿打印机误打出的奶娃主持人：纸卷胎毛、快递面单围兜、倒扣周转箱、比头还大的方章
- 首次进房播放约 4 秒登场：
  - 闸门落锁、讲台亮灯、胎毛从周转箱后露出，音箱弹出「咔啵」「咔啵」
  - 奶娃指向阿浣腰间旧扫码枪，问「你是什么手机？」
  - 阿浣扫码「滴。」，巨幕印出「灭霸｜本场主讲人」，奶娃给自己补章，镜头拉回战斗
- 演出期间暂停伤害、攻击和 Boss 计时；空格或点击可跳过
- 自然播完与跳过共用 `finishIntro` 收尾；跳过输入被消耗，控制权恢复后才出首招预警
- 用 Registry 的 `bossIntroSeen` 区分首次与同局重试；从标题开始新局才清除
- 同局死亡 → 结算 → 重试直接回到 Boss 房，不再从关卡开头跑

### 2.5 两个梗的 Boss 招式

- 第一阶段 `radish_stamping`：机器人浇水、萝卜开花、巨章盖「类魂」并飘字「又是类魂」；演出结束后才出现三选一和 2 秒窗口
  - 答对：尾巴弹章、同一声扫码「滴」、「类魂」贴到围兜，浇水机转向奶娃；沿用反伤、硬直、掉卡
  - 答错/超时：沿用扣血、揭示答案和各自统计
- 第二阶段 `auto_signing`：宣布「全自动签收！」，三枚章依次举起，第一道门的小票重新展开
  - 问「代签人是谁？」，选项灭霸/灭建国/阿浣
  - 答对：尾巴展开签收单接住前两枚章，第三枚弹回围兜盖「已签收」；沿用反伤、硬直、掉卡
  - 答错/超时沿用原受伤与揭示逻辑
- 第三阶段保留原有高潮招式，未改写

### 2.6 三连残影冲刺四拍音效

- `dash_combo` 新增一组同源金属印章音效，全部由 `AudioSystem` 的 WebAudio 合成，不引入外部音频素材
- 第 1 拍是短促金属「当」，与 Boss 染色和「三连残影冲刺！」浮字同帧出现；后续三拍分别绑定三次冲刺真正启动的 `setVelocityX` 回调
- 中间两拍像公章擦过金属导轨，收尾拍更厚、尾音更长；四拍沿用同一组不和谐金属泛音
- 不改变攻击速度、伤害判定、冲刺间隔或躲避窗口；静音只关闭声音，染色、浮字和冲刺动作照常
- 硬直、特殊招、阶段转换、玩家/Boss 死亡和场景 shutdown 都会切断该组音效总线，后续拍点不再触发

### 2.7 第二幕「荒野岛」舞台与取景框教学

- 荒野岛为横向舞台，包含海雾、逆光、断桥和前后景平台；登陆点有被风吹向一侧的褪色防水布、挂在缆绳上的歪斜路牌、卡在远处树枝里的补给箱，以及第一幕用过的「已签收」箱盖
- 无人机先拍空箱：地面四角框合拢、快门「咔」、补给网只罩住空箱；第二个取景框转向阿浣，并留出移动/冲刺的预警时间
- 取景框同时用角框形状、合拢动作和文字标签表达，不只靠颜色；静音下仍可完整学习
- 被框罩住只锁一小段时间，不扣血；成功躲开有明确反馈。教学只在首道门未通过时播放，从检查点复活不会重复
- 新增补给搬运蟹：钳上顶着罐头盖，举盖蓄力后再突进；近距离射击可打断。举盖有空罐碰响，无人机有对焦/快门声
- 第一幕四拍金属音效仍是灭霸专属，第二幕不重复使用

### 2.8 第二道门之前的「亡命天涯」

- 荒哥在闸机旁录制逃生演示，立起「唯一退路」路牌；无人机拉紧缆绳，把荒哥和路牌一起拖出画面，地上刮出「亡命天涯」
- 问题「刚才路牌拖出了哪四个字？」；答对后阿浣抓住拖回来的缆绳，放下断桥
- 演出建立「缆绳绷紧＝正在拖拽」的规则，供 Boss 第二阶段复现
- 通过后写入 `RunState.act2Door1Passed`，解除断桥屏障，生成临时营地检查点，并进入三选一梗卡

### 2.9 「这是好事呀」货架门

- 雨棚漏水，水滴进空桶；演示中水桶变重，滑轮把挡路货架短暂吊起又落下
- 问题「荒哥说这是好事，究竟好在哪？」，选项中只有「水桶变重，吊起货架」成立，不依赖原梗背景也能推理
- 答对后桶标为「满桶」、货架升到顶部、碰撞屏障移除，生成第二个检查点并进入梗卡三选一；答错会重置演示水位和「空桶」状态
- 各门分别记录通过、奖励与检查点状态；从第一幕进入会清空第二幕门状态，第二幕复活保留已通过的门，不与第一幕的 `door1Passed` / `door2Passed` 混用

### 2.10 荒哥 Boss

- 两管血、三招式：第一管 720（「镜头跟上」）；第二管上限与当前血量均为 **1440**（第一管最大值的 2 倍），前半段「想链接了」，血量降到 50% 后进入「这是好事呀」招式升级，但血条不重置
- 第一管血打空只播放假胜利：荒哥跪下、自拍杆垂下、Boss 血条收回、音乐断半拍，右侧直播灯变红；不结算、不存档、不掉卡、不退出战斗。荒哥看一眼零数据后推满直播杠杆，只说「十倍杠杆。」；血条在原位展开为两条等长刻度，HUD 亮起「第二阶段」，直播数据面板单独显示「杠杆 ×10」
- 第二管开始时 Boss 回到场地中央、发白染色清除，HUD、血量和阶段同帧更新；首招保留完整预警。第一管只触发一次假胜利
- 首次进房播放约 4 秒登场，可等完或按空格/点击跳过：
  - 镜头沿绷紧的缆绳移动，观众以为荒哥在另一端，实际只有纸板「荒哥正在抵达」
  - 真荒哥从下方爬上，扶正自拍杆；无人机对焦、快门一闪，弹出「荒哥 · 本期节目主持人」名牌
  - 跳过输入被消耗，镜头与 HUD 归位后才开战；同局重试不再播放
- 普通攻击：取景框扫向玩家，首轮合拢较慢（约 2.1 秒），之后约 1.65 秒；框合拢后补给网落下。另有营具抛掷。持续射击、移动和冲刺沿用第一幕手感
- 第一管特殊招「亡命天涯」：缆绳绷紧，路牌扫过舞台，弹出「路牌被缆绳拖走时，地上刮出哪四个字？」。答对后阿浣把绳扣挂上自拍杆，无人机拖走荒哥自己的营具，造成反伤与硬直并掉卡
- 第二管前半段特殊招「想链接了」：荒哥举自拍杆，无人机挂钩先追踪玩家、绷绳锁方向，再执行拖拽；移动或冲刺可躲开。随后先给钩头和路牌拖痕回放，再开 2 秒题「刚才被它拖走的是？」。答对后阿浣甩尾把钩扣回自拍杆，自拍杆被拽长三节、直播画面只剩一只眼睛，荒哥才说「哎呀。」，随后结算反伤与 4.2 秒硬直
- 第二管后半段（≤50%）招式升级为「这是好事呀」：雨棚漏水、满桶悬在荒哥上方，弹出「满桶悬在雨棚上方，阿浣该做哪一步？」。答对后放松滑轮，雨棚兜住荒哥，造成反伤、更长硬直并掉卡；同时循环出现三处预警的水柱
- 弹反窗口约 2 秒，从选项可读且输入生效时开始；答错/超时沿用统一扣血与揭示逻辑。每个阶段招式的反伤、硬直、奖励和音效只结算一次；反伤跨阶段时不会丢失已获得的卡
- 真正清空第二管血后，阿浣递上一大瓶水，荒哥喝一口，把「这是好事呀」翻到背面「本期拍摄完毕」，停顿约半拍后进入第二幕正式结算；失败结算后，已通过第二道门则重试直接回 Boss 房，否则回岛上检查点

### 5.6 第一幕地面碰撞回归（2026-11-20）

现象：进入第一幕后开枪、连按或同时按 `J` / `K`，阿浣掉到可见地面下方，出现「你掉出了包裹分拣线。」；淡出复活后继续坠落。地面画面与物理实体独立，截图里地板仍在不能证明碰撞体还在。

- **版本对照**：
  - 当前分支 `feature/act2-wild-island` / `e8dc6cb`：重新构建后为 `assets/index-BfSW1mG5.js`，在 `vite preview`（最终复跑 5204，同一产物）用正常键盘从首页进入。
  - 旧版 `main` / `cd887d6`：在独立临时 worktree 构建为 `assets/index-B3wQfv2W.js`；该版本生产包不暴露调试句柄，因此同一源码改用开发服务器（5203）读取碰撞对象，未修改游戏逻辑。
  - 线上公开链接当前加载 `assets/index-j5sj5N2M.js`；它不是本次当前构建，也不等于旧版 `cd887d6`。
- **根因**：
  - 旧版 `LevelScene.setupCollisions()` 对 `collider(this.bullets, this.solids, (bulletObj) => bulletObj.destroy())` 直接假定第一个回调参数是子弹。Phaser 在这条“子弹组 vs 静态地面数组”路径上先把地面/平台传给回调，于是被销毁的是地形，子弹反而保留。
  - 实测旧版按住 `J` 时，子弹先命中 `solid[5]` 平台、再命中 `solid[0]` 起始地面；两者 `active=false`、静态物理体 `body.enable=null`，但子弹仍 `active=true`。起始地面碰撞体消失后，玩家从 `y=603` 落到 `y>640`，复活点仍在 150，于是反复坠落。
  - `471c316` 新增 `projectileFrom(group, a, b)`，按子弹组归属识别弹体，只销毁子弹；当前 `e8dc6cb` 已包含该修复，本次不需要改游戏代码。
- **同输入回归**（当前版生产预览 / 旧版开发服务器）：
  - 站立按住 `J`、只按 `K`、按住 `J` 连点 `K`、`J/K` 同时按下、交替连按：当前版所有场景 `solid[0]` 保持 `active=true`、`body.enable=true`，玩家稳定在 `y≈603`、`blocked.down=true`，无复活；旧版除只按 `K` 外，其余四个开枪场景均销毁 `solid[0]`，随后连续复活 2–4 次并继续坠落。
  - 当前版子弹命中 `solid[0]` / `solid[5]` 后，回调后地形仍活动、子弹 `active=false`；旧版回调后地形已销毁、子弹仍活动。
  - 主动跳入 1200–1370 缺口：当前版与旧版都只结算一次坠落，复活后回到起始地面并稳定站立；说明检查点与复活路径本身正常，异常只在旧版地面被子弹销毁后出现。
- **回归检查**：
  - 新增 `tests/act1-floor-collision.mjs`；命令 `npm run test:act1-floor -- http://127.0.0.1:5201/`（自动附加 `?debug=1`，正常键盘进入，不传送、不改血量）。
