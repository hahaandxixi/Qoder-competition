# 《浣熊火箭：无名氏危机》开发进度

- 更新时间：2026-11-18
- 当前版本：0.1.0（第一幕「发布会大厦」扩展版）
- 仓库：https://github.com/hahaandxixi/Qoder-competition
- 协作分支：`feature/act1-three-memes`
- 形态：Phaser 3 + Vite + TypeScript，纯静态站点，无后端、数据库、外部 CDN

## 1. 当前结论

第一幕已形成完整的「代签单 → 365 里路 → 奶娃主持人」体验：

**标题 → 第一幕跑跳/射击 → 代签单名字门 → 365 里路倒带名字门 → 奶娃主持人登场 → 第一阶段「又是类魂」→ 第二阶段「全自动签收」→ 第三阶段原高潮 → 胜利/失败结算 → 同局 Boss 死亡重试或返回标题**

`npm run build` 已在本机成功生成 `dist/`，TypeScript 严格检查通过。第一幕已发布到 Qoder Sites（public）：https://raccoon-rocket-ajj0fzwid68.qoder.zone 。本轮 `dash_combo` 四拍音效随协作分支提交，线上版本以对应发布记录为准。

## 2. 已实现内容

### 2.1 舞台与射击手感

- 保留左右移动、二段跳、土狼时间/跳跃缓冲、射击、冲刺（带无敌帧与残影）、梗卡与梗浓度槽
- Boss 房补了横版发布会舞台：褪色巨幕、快递传送带、升降台、讲台、垂下的卷曲面单；阿浣在左、演示物在中、甄领先在右
- 射击首次按下立即出弹，按住稳定连发，松开停火；枪口短闪、扇形弹道、命中闪白与音效沿用原系统
- 普通射击使用轻量反馈；完美弹反保留明显顿帧、震屏和闪白

### 2.2 第一道名字门「代签单」

- 收发室包裹、按铃、机器打印小票，答题时面单留在视野内
- 小票三行：收件人 甄领先 / 代签人 甄建国 / 与收件人关系 父
- 问题「谁替甄总签了包裹？」，选项含甄领先/甄建国/阿浣/收发员
- 答对盖「代签有效」，尾巴卷走签收联，门闩打开，进入原有三选一梗卡
- 答错可重试；门状态写入 `RunState.door1Passed`，检查点复活后仍可继续
- 这张签收联在 Boss 第二阶段重新展开

### 2.3 第二道名字门「365 里路」

- 玩家先看到近处取件窗口；按铃后窗口沿轨道滑远
- 吐出「取件请绕行 365 里」路线单，纸路一头连窗口、一头缠双轴磁带机
- 问题「按哪个键，能把这条路收回来？」，选项为播放/快进/倒带/录音
- 答对：线轴反转、纸路回卷、窗口拖回、取件铃响，窗口开成 Boss 房入口
- 各自记录 `door2Passed`、奖励、出生点与检查点状态；答错可重试
- 原创吐纸、滚轴、取件铃音效仍由 WebAudio 合成，无外部素材

### 2.4 奶娃主持人甄领先

- Boss 外观改为报废育儿打印机误打出的奶娃主持人：纸卷胎毛、快递面单围兜、倒扣周转箱、比头还大的方章
- 首次进房播放约 4 秒登场：
  - 闸门落锁、讲台亮灯、胎毛从周转箱后露出，音箱弹出「咔啵」「咔啵」
  - 奶娃指向阿浣腰间旧扫码枪，问「你是什么手机？」
  - 阿浣扫码「滴。」，巨幕印出「甄领先｜本场主讲人」，奶娃给自己补章，镜头拉回战斗
- 演出期间暂停伤害、攻击和 Boss 计时；空格或点击可跳过
- 自然播完与跳过共用 `finishIntro` 收尾；跳过输入被消耗，控制权恢复后才出首招预警
- 用 Registry 的 `bossIntroSeen` 区分首次与同局重试；从标题开始新局才清除
- 同局死亡 → 结算 → 重试直接回到 Boss 房，不再从关卡开头跑

### 2.5 两个梗的 Boss 招式

- 第一阶段 `radish_stamping`：机器人浇水、萝卜开花、巨章盖「类魂」并飘字「又是类魂」；演出结束后才出现三选一和 2 秒窗口
  - 答对：尾巴弹章、同一声扫码「滴」、「类魂」贴到围兜，浇水机转向奶娃；沿用反伤、硬直、掉卡
  - 答错/超时：沿用扣血、揭示答案和各自统计
- 第二阶段 `auto_signing`：宣布「全自动签收！」，三枚章依次举起，第一道门的小票重新展开
  - 问「代签人是谁？」，选项甄领先/甄建国/阿浣
  - 答对：尾巴展开签收单接住前两枚章，第三枚弹回围兜盖「已签收」；沿用反伤、硬直、掉卡
  - 答错/超时沿用原受伤与揭示逻辑
- 第三阶段保留原有高潮招式，未改写

### 2.6 三连残影冲刺四拍音效

- `dash_combo` 新增一组同源金属印章音效，全部由 `AudioSystem` 的 WebAudio 合成，不引入外部音频素材
- 第 1 拍是短促金属「当」，与 Boss 染色和「三连残影冲刺！」浮字同帧出现；后续三拍分别绑定三次冲刺真正启动的 `setVelocityX` 回调
- 中间两拍像公章擦过金属导轨，收尾拍更厚、尾音更长；四拍沿用同一组不和谐金属泛音
- 不改变攻击速度、伤害判定、冲刺间隔或躲避窗口；静音只关闭声音，染色、浮字和冲刺动作照常
- 硬直、特殊招、阶段转换、玩家/Boss 死亡和场景 shutdown 都会切断该组音效总线，后续拍点不再触发

### 2.7 数据与工程

- 题目、梗卡、Boss 阶段/招式、UI 文案仍在 JSON：`src/data/questions.json`、`cards.json`、`bosses.json`、`strings.json`
- 时间、伤害、弹反窗口、特殊招冷却等集中在 `src/config/balance.ts`
- `tsconfig` 开启 `strict`、`noUnusedLocals`、`noImplicitOverride`；未使用 `any`
- 新增 `Hud.setVisible`，登场时隐藏战斗 HUD，镜头归位后恢复
- 生产预览可加 `?debug=1` 暴露测试句柄；正常地址不暴露
- 构建脚本 `scripts/build.mjs` 继续固定项目内临时目录，规避本机 Windows esbuild 临时目录权限问题

## 4. 运行与构建

```bash
cd D:\jbcode\Qoder-competition
npm install
npm run dev        # 开发预览，默认 http://127.0.0.1:5173
npm run typecheck  # TypeScript 严格检查
npm run build      # 类型检查 + 生产构建，输出 dist/
npm run preview    # 本地预览 dist/
```

生产预览的自动验收可在地址后加 `?debug=1`；正常游玩不带该参数。

### 操作

- 桌面：A/D 移动，空格二段跳，J 射击，K 冲刺，E 交互，1/2/3 作答，Z/X/C 使用梗卡，M 静音
- 手机：左下角左/右移动，右下角射击/跳跃/冲刺/交互，答题与梗卡直接点选
- 手机建议横屏；竖屏会显示旋转提示

### 从首页玩到三个梗

1. 标题点开始，向右到收发室，按 `E`，答「谁替甄总签了包裹？」→ **甄建国**
2. 继续向右到取件窗口，按 `E`，看窗口滑远，答「按哪个键，能把这条路收回来？」→ **倒带**
3. 进 Boss 看完/跳过登场；第一阶段答 **类魂**，第二阶段答 **甄建国**，随后继续射击并清空第三阶段

## 5. 本次验证记录

验证环境：Windows，Node 24.22.1，本机 Chrome + `puppeteer-core` headless；脚本放在被忽略的 `.tmp-esbuild/`，不作为项目依赖提交。浏览器验收默认使用 `--mute-audio` 静音运行；三连残影冲刺音效专项测试使用未静音 headless WebAudio 输出截取。

- `npm run build`：通过（包含类型检查）；生成 `dist/index.html`、CSS 与 JS，仅有 Phaser 体积 chunk > 500 kB 提示
- **完整路线**（`flow-act1.mjs`）：
  - 从标题按钮点击进入关卡；跑向两道门后段并用 `E` 真实交互
  - 第一道门答对 → 门开 → 梗卡签收；第二道门窗口滑远 → 答倒带 → 门开 → 进 Boss
  - 首次登场自然播完；第一阶段「类魂」答对，弹反后 `J` 射击子弹 0 → 6；第二阶段「代签人」答对
  - 击破进入结算；`ERRORS []`
  - 为缩短长距离跑图与验证第三阶段结算，测试脚本使用了近门传送和一次测试伤害；不是一次完整的人工 3–5 分钟跑图
- **边界分支**（`edge-act1.mjs`）：
  - 点击跳过登场：`intro true → false`、`fight false → true`、HUD 隐藏后恢复
  - 第一阶段超时：血量 100 → 80，`timeouts +1`；随后额外按键不再结算
  - 第一阶段答错：血量 100 → 80，`wrong +1`；同一题再按正确答案不会二次结算
  - 第二阶段答对：Boss 500 → 410，`parries +1`，`correct +1`
  - 胜利结算后重试回关卡；同局 Boss 死亡后结算重试直接回 Boss（入场 `intro false`、`fight true`、血量 60）
  - `ERRORS []`
- **手机横屏**：844×390、`hasTouch` 模拟；答案清晰可读，触摸点选成功结算，`MOBILE_ERRORS []`
- **生产构建预览**：`vite preview` 于 `http://127.0.0.1:4173/?debug=1` 启动；标题、直接入战、死亡后重试直接回 Boss 均通过，`PROD_ERRORS []`
- **截图归档**：`docs/screenshots/` 下保存真实运行截图：登场、类魂演示、签收演示、类魂弹反、签收反打、手机答题、结算
- **三连残影冲刺四拍音效（受控浏览器测试）**：
  - 完整招式动作回调恰好 4 次：第 1 拍 `attackBusy=true`、Boss 尚无冲刺速度，染色预警已出现；第 2/3/4 拍回调内 `vx=-880`，与三次 `setVelocityX` 同步
  - 第 2 拍后硬直取消：只保留第 1/2 拍，音效总线增益降到 0.0001；场景重开后旧场景没有后续拍点
  - 截取 WebAudio 输出做高通瞬态检测：完整招式恰有 4 个起音（0.160/0.517/1.179/1.840s），2.3s 后 RMS 约 3.7e-5；第二拍后切断，0.65s 后 RMS 约 5.2e-5、随后为 0
  - 静音下仍触发 4 拍动作与染色预警，未创建音效总线
  - 该测试通过受控场景进入 Boss，未使用正常入口完整跑图；真人听感/混音仍待验证

## 6. 已知问题与技术债

- 未接入正式自动化测试框架或 lint；当前验证依赖临时 headless 脚本，脚本未提交
- Phaser 打包 chunk 约 1.67 MB（gzip 约 396 kB），构建提示体积警告；不影响静态部署
- 手机横屏 390px 高度下 HUD 与虚拟按键较密；已复核答题可读可点，但世界教学牌部分仍写键盘键位
- 手机端竖屏只提示旋转，不提供竖屏重排布局
- 卡牌描述中的中文换行为人工控制，修改 `cards.json` 文案时需同步检查
- 目前只有静音与最佳记录持久化，没有账号、云存档或后台数据
