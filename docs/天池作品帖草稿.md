## 二、作品是什么

《浣熊火箭：无名氏危机》是一款 **2D 横版跑跳射击 + 认梗弹反** 的网页游戏：一只背着废铁火箭的浣熊“阿浣”，在名字被偷走的废土快递世界里，靠认出热梗夺回名字。完整一局约 3–5 分钟，包含两幕、四道名字门、两个 Boss。

- **第一幕「发布会大厦」**：代签单、365 里路两道名字门 → 紫色奶娃主持人「灭霸」三阶段 → 阿浣击败台词「灭霸这个扎啤」→ 半张荒野岛面单。
- **第二幕「荒野岛」**：无人机取景框教学、断桥导弹、亡命天涯/这是好事呀两道门 → 荒哥第一管血假胜利「十倍杠杆」→ 第二管 1440 血、挂钩弹反 → 正式结算「本期拍摄完毕」。
- **梗弹反**：Boss 蓄力时出现 2 秒选项，认对就反弹伤害、硬直、掉梗卡；答错/超时扣血。前期看到的面单、路牌、水桶，都会在后面的题里再次出现。
- **两种快递陷阱**：第一幕“已签收，请退后”盖章陷阱，可以用补给压板贪一下再退，也能把负鼠引进章影；第二幕“快递原路退回”，去程件进回收口后原路退回，需要看灯、看方向、选时机。
- **小怪语音**：背手负鼠扑空后嘟囔“扎啤吧？”、龙虾机器人首次开炮“遥遥领先”、无人机锁定“我要验牌！”、守门负鼠“你的胆子真是肥嘟嘟的”。
- **美术/音频**：角色、场景、UI 全部代码程序化绘制；音效与配乐为 WebAudio 实时合成（原创，不使用商业歌曲/影视片段）；角色语音为 6 条系统 TTS 生成的占位 MP3，字幕同步，后续可替换。
- 支持桌面键盘与手机横屏触控，纯静态网页，无后端、无外部 CDN。

## 三、为什么做

LifeHack 赛道里，肉鸽、割草、人生模拟和照片生成已经很热闹。我们想做一个**评委第一眼能看懂、第一局能亲自用上**的差异点：不把“梗”做成贴纸或彩蛋，而是把它做成唯一的成长资源和战斗核心——**懂梗，就能打回去**。

三个具体的取舍：

1. **认梗不是背题库**。名字门先给纸面线索（例如代签单三行字），Boss 战再把同一张纸展开；第一次玩的同学靠观察也能答出来，而不是必须刷过原视频。
2. **两秒弹反保留紧张感**。Boss 出招、截图、认梗、按键，四件事压在两秒里；答对给明显顿帧、震屏和反伤，答错给答案和重试机会。
3. **题材做安全边界**。人物全部是虚构玩梗形象，不出现真实姓名、公司、Logo、真人肖像；不搬运商业歌曲、影视片段或原视频音频。我们只保留“梗的公共语义”，所有美术、音效、配乐自己生成。

## 四、五步以内怎么玩

桌面：`A/D` 移动，`空格` 二段跳（**按住**跳得高，空中再按一次二段跳），`J` 射击，`K` 冲刺，`E` 交互，`1/2/3` 作答，`Z/X/C` 用梗卡，`M` 静音。手机横屏直接点屏幕按键和选项。

1. 标题点「签收任务」。沿发布会大厦向右，遇到第一道收发室门，按 `E` 按铃，看小票三行：收件人灭霸 / 代签人灭建国 / 关系父；答「灭建国」，门开并抽一张梗卡。
2. 继续向右到取件窗口，按 `E` 按铃；窗口滑到 365 里外，答「倒带」把它拖回来；再按 `E` 进入 Boss 房。
3. 灭霸登场可看完或按空格跳过。第一阶段认「类魂」，第二阶段认「灭建国」；答对会反伤并硬直，趁硬直按住 `J` 输出，清空最后一阶段。阿浣会说一次「灭霸这个扎啤」，随后进入结算，点「前往荒野岛」。
4. 荒野岛先看无人机对空箱的取景框示范；到断桥前先看安全岸的导弹演示，**退一步等导弹掠过再按住空格二段跳**。第一道门看挂钩拖走路牌，答「亡命天涯」；第二道门看漏水吊货架，答「水桶变重，吊起货架」。
5. 荒哥第一管血打空只会播「十倍杠杆」假胜利，不会结算；第二管 1440 血开场躲开钩子后答「路牌」，后半段答「放松滑轮，雨棚兜住荒哥」；真正清空第二管血，荒哥喝水把节目牌翻到「本期拍摄完毕」，进入最终签收单。

> 第一幕的两个坑需要按住空格二段跳；游戏在第一个缺口前和首次掉坑复活后都有“按住 SPACE 起跳，空中再按一次”的提示。

## 五、怎样用 Qoder 开发与部署

- **开发**：用 Qoder CN 的对话式开发推进 Phaser 3 + Vite + TypeScript 工程；把题目、梗卡、Boss 阶段、台词、数值拆进 `src/data/*.json` 与 `src/config/balance.ts`，方便队友并行改内容。美术没有外部素材，统一用 Canvas 程序化纹理；音效/配乐用 WebAudio 实时合成；语音用系统 TTS 生成 6 条占位 MP3，字幕与语音同源。
- **验证**：`npm run typecheck`、`npm run build`；仓库内 `npm run test:act1-floor -- <生产预览地址>` 回归“连射不会打掉地面”；另外用 headless Edge 在生产预览跑两幕门、Boss、陷阱和语音状态。开发期间的临时自动化脚本不提交，稳定回归才放进 `tests/`。
- **部署**：Qoder Sites 以 public 静态站发布。公开站已上线两幕完整版（`c684a88`，`assets/index-KKkfEmb_.js`）；本次 `release-polish` 的发布前优化构建 `assets/index-DwcF0Nf7.js` 已通过本地生产预览，最终发布后需从公开首页复测新版独有行为（例如负鼠扑空后的“扎啤吧？”语音，或盖章陷阱压中负鼠）。
- **Qoder 账号**：Qoder Sites 站点所有者账号（发布时填写实际账号）。

### 开发过程实例：同学连按 J/K 发现穿地

一位同学在试玩时按住 `J` 连射、同时连点 `K` 冲刺，阿浣突然掉到可见地面下方，复活后还在继续坠落。我们没有先改数值，而是对照两个版本：

1. 旧版 `main` / `cd887d6` 的生产包不暴露调试句柄，就在独立工作树用开发服务器读取碰撞对象；当前分支用生产预览读取同一对象。
2. 日志显示：子弹碰到地面的 collider 回调里，被销毁的是**地面**，子弹反而留着。Phaser 在这条“子弹组 vs 静态地面数组”路径上把地面作为第一个参数传进来，旧代码 `(bulletObj) => bulletObj.destroy()` 直接假定第一个参数是子弹。
3. 修复：新增 `projectileFrom(group, a, b)`，按子弹组归属识别弹体，只销毁子弹；旧地面保持 `active=true`、`body.enable=true`。
4. 回归：把复现步骤固化为 `tests/act1-floor-collision.mjs`；当前版 `[pass]`，旧版稳定报 `floor collider was destroyed by a bullet collision`。公开站重新发布后，还要按同一输入在公开首页再走一次。

这个例子后来也影响了这次首轮修复：负鼠“看起来能打中却打不中”时，我们先量了纹理尺寸和物理体，而不是先调伤害——最后发现是 54×54 的可见头部只有 38px 高的命中框，子弹从头顶过去了。
