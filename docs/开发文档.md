## 3. 形态决策：网页 vs 游戏引擎 vs 小程序

先澄清：**"游戏引擎"是开发方式，"网页"是交付形态**，不是二选一。比赛只认 Qoder Sites 静态站点链接，所以交付形态只能是网页；问题是用什么来开发这个网页。

| 方案 | 满足 Qoder Sites 公网要求 | 2 周内开发速度 | 评委体验 | 结论 |
|---|---|---|---|---|
| 微信小程序 | ❌ 无法托管在 Qoder Sites，要审核上架，不能"点开即用" | 中 | 差 | **排除** |
| 纯手写 Canvas/JS | ✅ | 慢（物理、碰撞、场景、音频全自研） | 好 | 备选 |
| **Phaser 3（Web 游戏引擎）** | ✅ 构建产物就是静态站点 | 快（物理/场景/输入/音频开箱即用） | 好 | **采用** |
| Unity / Godot Web 导出 | ✅ 但包体 MB 级、加载慢、构建链重 | 慢 | 一般 | 排除 |

**最终选型：Phaser 3 + Vite + TypeScript，构建成纯静态网页，部署 Qoder Sites（public）。**

理由：
1. 交付形态天然满足比赛要求，`npm run build` 的 `dist/` 原样上传，天然满足"公开包与本地构建逐字节一致"
2. Phaser 3 为 MIT 协议，公开资料极多，Qoder 生成和迭代代码的准确率最高
3. 2D 横版闯关需要的 Arcade 物理、帧动画、场景管理、触屏输入、WebAudio 全部内置
4. 纯前端无后端：无登录、无接口、无 404 风险，0 报错目标可控
5. 所有资源本地打包（不用任何 CDN 外链），避免外链失效和跨域报错

## 4. 游戏设计

### 4.1 世界观

反派"无名氏"偷走了互联网梗的名字，梗失去名字就失去力量。主角浣熊"阿浣"每认出一个梗，就把名字从反派手里抢回来，梗化为可以装备的战斗能力。

### 4.2 核心循环（单局 3–5 分钟）

```
平台跳跃推进 → 小怪/陷阱 → 名字门（慢速答题，选卡/回血）
→ Boss 战（快速梗弹反 + 常规射击）→ 结算 → 下一幕
```

### 4.3 梗弹反（核心机制，优先级最高）

- Boss 释放标志性招式时头顶弹出台词气泡（如"遥遥领先！"）
- 屏幕出现 3 个梗名选项，**答题窗口 2 秒，不暂停战斗**
- 答对：完美弹反——Boss 硬直 8 秒、招式反噬、掉落一张梗卡（每阶段限一次）
- 答错/超时：正常吃伤害（约 20% 血），并短暂显示正确梗的提示
- 桌面用数字键 1/2/3 作答，手机点按钮，UI 同一套

### 4.4 名字门（慢速答题）

- 挡路的保险箱，4 选 1，答对开门并 3 选 1 抽梗卡+回血 30%
- 答错：门嘲讽，5 秒后可重试，或选择"硬闯"（触发一波小怪）

### 4.5 梗卡（答对奖励）

| 卡名 | 效果 | 触发梗 |
|---|---|---|
| 大水 | 回满血 | 弱者喝饮料，强者喝大水 |
| 画地为牢 | 定身 Boss 3 秒 | 画地为牢啊，厉娜 |
| 广智救我 | 召唤小弟代打 10 秒 | 广智救我 |
| 梆梆两拳 | 攻速翻倍 5 秒 | 冷不丁梆梆就两拳 |
| 亡命天涯 | 冲刺无 CD 8 秒 | 亡命天涯 |
| 这是好事呀 | 受伤转护盾 5 秒 | 这是好事呀 |
| 遥遥领先 | 移速+攻速 5 秒 | 遥遥领先 |
| 比个拉布 | 全屏声波清屏 1 次 | 比比拉布 |

另设"梗浓度"槽：答对累积 0–100，连对有倍率，满槽触发"全民玩梗"模式（5 秒双倍伤害）。

### 4.6 Boss 与人物替换

| 原型 | 游戏内角色 | 保留的梗 | 招式 | 合规红线 |
|---|---|---|---|---|
| 科技发布会 CEO | **灭霸**（遥遥集团） | 遥遥领先 | P1 三连残影冲刺；P2 跑分无人机弹幕；P3 高端化红毯收缩场地 | 紫色奶娃主持人像素造型；不用真名/真公司/Logo；失败演出体面 |
| 户外整活主播 | **荒哥** | 亡命天涯、这是好事呀 | 荒野关饥饿 debuff；踹翻无人机；"拽出屏幕"把玩家拉向屏幕边缘 | 只有"户外主播"人设；不提真名与真实事件（约战拳王事件绝对不用） |
| （原户晨风） | **删除**；如需要唇枪角色，用纯原创「杠老哥」 | — | 杠老哥会篡改你的题目选项，考验识破能力（可选扩展） | 被封禁人物 + 阶级对立内容，双高风险，不做 |

已发布作品占用情况：不烧心、奶蛙已被其他队伍使用，本作避开；龙虾击破台词改为原创「过载了，请重新取号。」。

### 4.7 主角与操作

- 主角：浣熊"阿浣"，武器为废铁霰弹（短距散射，自动连发）
- 操作：A/D 移动，空格二段跳，J 射击，K 冲刺，E 交互/答题，1/2/3 作答
- 手机：屏幕左虚拟摇杆 + 右侧射击/跳跃/冲刺三键；答题直接点选项

### 4.8 关卡与 MVP 范围

| 关卡 | 内容 | Boss |
|---|---|---|
| 第一幕 发布会大厦 | 跑图 + 小怪（背手负鼠偷 buff、龙虾机器人巡逻） + 2 道名字门 | 灭霸（3 阶段） |
| 第二幕 荒野岛（加时内容） | 断桥导弹 + 陷阱 + 2 道名字门 | 荒哥（双血条，三套招式） |

- **MVP（必做）**：第一幕 + 灭霸 + 12 道题 + 6 张卡，全链路可通
- **加时（11-22 后评估）**：第二幕 + 荒哥 + 题库扩到 24 道

### 4.9 视觉与音频

- 视觉：废土拼贴像素风，Canvas 程序化绘制（实施说明 2026-11-21：实际构建未使用 Kenney 素材；角色/场景/UI 全部程序化绘制，音效与配乐为 WebAudio 合成，角色语音为 6 条系统 TTS 占位 MP3）
- 音效：WebAudio 合成 8-bit 音效与原创洗脑循环 BGM（**不搬运任何原视频音频**）
- UI：快递面单式的"梗卡"边框 + 屏幕震动/顿帧等打击感

## 5. 技术架构

### 5.1 技术栈

| 层 | 选型 |
|---|---|
| 游戏引擎 | Phaser 3（MIT） |
| 构建 | Vite + TypeScript |
| 状态保存 | localStorage（JSON 序列化，try/catch 包裹） |
| 数据 | 本地 JSON（题库/卡池/Boss 配置），随构建打包 |
| 部署 | Qoder Sites 静态托管，public |

### 5.2 目录结构

```
jzx-code/
├─ docs/开发文档.md
├─ index.html
├─ vite.config.ts
├─ package.json
├─ public/                # 字体、音效（如用文件形式）、CC0 素材
└─ src/
   ├─ main.ts             # Phaser 初始化与全局配置
   ├─ scenes/
   │  ├─ BootScene.ts     # 预加载与程序化贴图生成
   │  ├─ MenuScene.ts     # 标题 + 操作说明 + 开始
   │  ├─ LevelScene.ts    # 跑图关卡（复用两张地图配置）
   │  ├─ BossScene.ts     # Boss 战（按配置加载不同 Boss）
   │  ├─ QuizOverlay.ts   # 名字门 / 弹反答题 UI（场景叠加）
   │  └─ ResultScene.ts   # 结算 + 重开
   ├─ systems/
   │  ├─ ParrySystem.ts   # 弹反判定与窗口管理
   │  ├─ QuizSystem.ts    # 抽题、判分、提示
   │  ├─ CardSystem.ts    # 梗卡获取/生效/过期
   │  ├─ MemeMeter.ts     # 梗浓度与连对倍率
   │  └─ SaveSystem.ts    # localStorage 读写
   ├─ data/
   │  ├─ questions.json   # 题库
   │  ├─ cards.json       # 梗卡
   │  └─ bosses.json      # Boss 阶段/招式/弹反题映射
   └─ art/                # 程序化像素贴图函数
```

### 5.3 场景状态机

```
Boot → Menu → Level(act1) → Boss(灭霸) → Result → Menu
                    ↘ QuizOverlay（叠加，暂停物理）
Boss 内部：Phase1 → Phase2 → Phase3 → 死亡演出
```

`questions.json`：

### 5.5 关键实现约定

- 「公开包与本地构建逐字节一致」：部署只上传 `npm run build` 产物，不手改 dist；提交前重新 build 一次
- 「0 报错」：所有资源打包进产物，无任何外链请求；音频在用户首次点击后初始化（绕开自动播放限制）；`localStorage` 读写包裹 try/catch；窗口 resize 统一由 Phaser Scale Manager 处理
- 性能：目标 60fps；同屏粒子数上限 200；贴图尺寸不超过 512×512
- 兼容：Chrome/Edge 桌面 + iOS Safari + Android Chrome；竖屏提示"横屏游玩更佳"但可继续

## 6. 合规与原创

### 6.1 人物与梗的处理

1. 名字全部替换（灭霸 / 荒哥），不出现真实姓名、真公司、真产品名、Logo
2. 形象仅用高抽象像素画/剪影，不做可识别面部和标志性穿搭；不配真实照片
3. 不写贬损、违法、道德指控类情节；Boss 失败演出一律体面
4. 台词只用广泛流传的短梗；不搬运原视频、原音频、原 BGM（全部自制合成）
5. 题目只问梗、不问真人（例："遥遥领先"常被用来模仿什么场合 → 科技发布会）
6. 删除户晨风相关内容（被封禁人物 + 阶级对立题材，双重风险）
7. 游戏内 Credits 页放声明："本作人物均为虚构，纯属玩梗娱乐，与任何真实人物无关；角色/场景/UI 与音效/配乐均由代码程序化生成，角色语音为系统 TTS 占位音。"

> 注：以上为常规风险控制，非法律意见。

### 6.2 原创策略

- 引擎与工具（Phaser、Vite）为 MIT 开源，正常使用不算抄袭
- 游戏代码、关卡、数值、题库、美术、音频全部自己编写/生成，不下载他人游戏改编
- 素材来源在帖子与 Credits 页标明（程序化自制 / WebAudio 合成 / 系统 TTS 占位语音）

### 6.3 帖子中的原创声明

「本作品为本次大赛期间原创，代码、关卡设计、题库、程序化美术与 WebAudio 音效/配乐均为团队自制，角色语音为系统 TTS 生成的占位音（非真人录音、非商业歌曲或影视片段）；作品中人物均为虚构玩梗形象，与任何真实人物无关。」
